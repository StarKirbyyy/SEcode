# 阶段 01：需求、范围与验收标准

## 1. 阶段目标

将原始考核题目转化为可追踪、可验证、可为设计决策辩护的项目需求，锁定首版边界和最终交付条件。

## 2. 前置输入与需求来源

- 原始题目：[推免考核题目学生版.pdf](../推免考核题目学生版.pdf)
- 用户确认的产品方向：Next.js 本地单用户 Web 工作台。
- 用户确认的模型方向：DeepSeek 与可配置 LongCat 兼容端点。
- 用户确认的安全方向：分级自动执行，危险操作审批。
- 用户确认的持久化方向：JSONL 事件日志。

## 3. 项目目标

实现一个不依赖 Agent 框架的编程智能体。它能通过大语言模型原生工具调用，在指定本地工作区内自主读取代码、修改文件、运行命令、验证结果，并通过 Web 工作台向用户呈现完整过程。

## 8. 首版范围

### 范围内

- 本地单用户 Web 应用。
- 一个会话固定绑定一个工作区和一个模型配置。
- DeepSeek、LongCat 和通用 OpenAI 兼容 Chat Completions。
- 六个结构化本地工具。
- 风险分级、单次审批、取消和错误恢复。
- JSONL 会话存储与上下文压缩。
- 中文工作台、核心自动化测试和提交材料。

### 范围外

- 远程多租户、登录和权限系统。
- Docker/虚拟机级强沙箱。
- Git 自动提交、推送、发布和部署。
- MCP、浏览器自动化、图片理解和语音能力。
- 多 Agent 协作、计划树、长期后台任务。
- 服务端托管文件或代码执行 API。

## 9. 关键设计决策

1. Next.js 既提供页面也提供本地 Node.js API；不部署到无状态 Serverless 环境。
2. 模型层使用原生 `fetch`，以证明工具调用解析和循环由项目自行实现。
3. Agent 内部采用事件驱动状态机，JSONL 是可恢复过程的事实来源。
4. 每个会话固定工作区，切换路径时创建新会话，避免上下文混用。
5. 文件写入使用结构化工具；通用命令默认无 shell，并通过风险策略控制。

## 12. 反思与修正

### 发现的问题

1. “工作区限制”不是强操作系统沙箱；任意获批进程仍可能产生工作区外副作用。
2. LongCat 没有可稳定写死的统一公开云端地址。
3. 上下文压缩如果破坏 assistant/tool 配对会导致模型协议错误。

### 已修正的规格

1. 明确产品只面向可信本地用户，并将未知程序和 Shell 纳入审批。
2. LongCat 改为用户配置 `base URL`、模型 ID 和环境变量密钥。
3. 上下文只能按完整工具回合压缩，原始 JSONL 永不删除。

### 遗留风险

- 强沙箱不在首版范围，必须在 README 和界面中持续说明。
- 模型提供方的兼容差异需要在阶段 04 使用夹具测试覆盖。
